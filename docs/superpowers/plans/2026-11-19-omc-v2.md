# omc v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lift the source project's `omc/` into oh-my-clanker-v2 as a project-independent folder that `just install <project>`
copies into any repo and `/oh-my-clanker` integrates and later updates.

**Architecture:** v2 holds one folder, `omc/`, which is what a project receives: `config.yaml`, `omc.just` (imported
by the project's justfile), `pyproject.toml`/`uv.lock`, `pipeline/`, `terminals/`, `skills/`, `tools/`. Everything
else in v2 (`install/`, the root `justfile`, `AGENTS.md`) installs it and is never copied. Every path the source project hardcodes becomes
a `paths:` entry of `config.yaml`; a step whose paths are empty finds nothing and passes. The project's own commands
live in `omc/bin/`, created at install, never shipped.

**Tech Stack:** Python ≥3.14 (stdlib + pyyaml; iterm2 on darwin) run through `uv run --project omc --frozen python -I`,
unittest scripts as in the source project, `just` ≥1.59 (`import`), git, Dart for the links tool (as in the source project).

**Spec:** `docs/superpowers/specs/2026-11-19-omc-v2-design.md`

**Source:** the source project's checkout, commit `8805d16` (call it `$SRC`).

## Global Constraints

- No trace of the source project: `grep -rni <source name>` over the v2 tree (minus `.git` and `docs/superpowers/`) is empty.
- Code and skill text stay as the source project has them except: paths → `config.yaml`, gates → `omc/bin/`, and the cuts of
  the spec's "What is cut". No switches, flags, hook slots or extension points.
- Dormant by absence: an empty `paths:` list (or a missing file it points to) makes its steps report nothing and pass.
- Claude Code only. GitNexus always on.
- Stays in the source project, not lifted: DVC, debug-live, system-guided-run, e2e-tests, derive-scenarios, scenarios-review,
  `wiring-tests`, review-screens, the objects-generator rule, the whole-table-read rule, the macOS/VM screenshot rule.
- Prose: no citations of the source project's records (`D<n> of docs/superpowers/specs/2026-11-1…`, `B16`, `O3`); keep the rule
  each states. The owner is "the owner", pronoun "they".
- Never the cheap model tier (config.CHEAP stays).

## Review Focus

1. A fresh repo with no `docs/` at all: `just decisions check`, `just design-integrity-check`, `just omc record`,
   `just links-check` must pass quietly, not crash on a missing log or folder. (Tests in Tasks 2, 4, 5.)
2. A project that already has `check`/`build`/`verify` recipes in its justfile: `import 'omc/omc.just'` must not
   collide; omc.just defines no recipe of those names. (Test in Task 6.)
3. Update when the project deleted a shipped file, or v2 deleted one the project changed: the merge keeps the
   project's side and reports it, never silently resurrects or drops. (Test in Task 6.)
4. A gate that passed, then a commit only under `omc/bin/`'s notes or `paths.briefs`: the pass still holds; a commit
   anywhere else voids it. (Test in Task 3.)
5. `just install` on a dirty project tree or a non-repo: refused before writing anything. (Test in Task 6.)
